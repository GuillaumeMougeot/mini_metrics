# Continuous threshold checks

See the [threshold contract](../docs/threshold-contract.md) for supported behavior
and links to its regression tests.

Run from the repository root with Python 3.13+ and the development dependencies:

```bash
uv run --no-sync python -m pytest -q
uv run --no-sync python -m benchmarks.threshold_monitor --output benchmark-results/current.json
```

The default test suite takes about 16 seconds locally; the threshold modules take
about 4 seconds. CI runs correctness on Python 3.13 and 3.14, and saves JUnit results.
A separate job saves the monitor JSON on pull requests, main pushes, manual runs,
and weekly runs. All workloads are deterministic and require no `dev/` files.

## What fails a build

- Independent count-based Macro/Micro-F1 checks across every state of small seeded
  long-tail datasets, including confidence ties and prediction-only classes.
- Exact selection outside its requested **calibration** F1 tolerance.
- Loss of decision invariance under row permutation, replicated samples, class
  renaming, or strictly monotone confidence transforms in rejection-rate mode.
- Plateau geometry, tolerance boundaries, decimal tie breaking, float-adjacent
  confidence gaps, zero endpoints, or sparse midpoint acceptance/fallback changes.
- Generic search exceeding its evaluation budget, returning an unevaluated
  threshold, or exceeding tolerance against the best **evaluated** score.
- Existing public API routing, multilevel dispatch, example-data oracles and CLI
  goldens. Golden files are never regenerated by tests or the monitor.

The monitor itself also fails on undefined reporting P/R/F1 or exact calibration regret outside
tolerance. Its reference F1 uses explicit counts, independently of package F1.

## Performance and sensitivity measurements

The default monitor performs 40 measurements: exact Macro/Micro curves and
Macro/Micro/generic optimizers, at 256 and 2,048 rows, with both tied and continuous
confidences. The generic criterion has the same objective but disables the fast
path, making it a useful cost reference; its sparse resolution is different.
Five additional workloads cover in-memory CSV parsing, strided slicing,
instance-grouped splitting, and threshold application on ordered and interleaved
two-level hierarchies (2n rows for n source instances). CSV text is prepared
outside measurement; parsing is timed, disk I/O is not. Other workload
construction and imports are excluded. Each measurement has a warmup, five
wall-clock samples, and a separate traced-allocation run. JSON retains raw samples,
medians, peak traced bytes, environment versions and source hashes. Traced memory
is not process RSS and may omit allocations made by native dependencies.

Timing is advisory in shared-runner CI. Compare reports on the same idle machine
with the same dependencies, thread settings and workload configuration:

```bash
uv run --no-sync python -m benchmarks.threshold_monitor --output benchmark-results/before.json
# Make the implementation change, then:
uv run --no-sync python -m benchmarks.threshold_monitor --baseline benchmark-results/before.json \
  --output benchmark-results/after.json --max-ratio 1.5
```

This optional gate fails on median runtime or peak traced memory increases above
50%. It rejects mismatched configurations/environments and missing workloads.
Rerun a timing failure in isolation before attributing it to code. Inspect decreases
as improvements as well; these budgets are not a claim about asymptotic complexity.
Use `--sizes 256 2048 16384 --repeats 7` for larger scaling experiments.

Sensitivity runs use 12 seeded trials, nested calibration sizes 64/256, both
coordinate modes, and epsilons 0/.01/.05. A fixed disjoint reporting cohort has
1,024 rows. JSON records per-trial thresholds, calibration regret, reporting F1,
paired F1 difference from a higher-coverage argmax, public Macro-P/Macro-R,
coverage, and grouped threshold/P/R/F1/coverage SDs and loss
fractions. Epsilon zero still performs plateau/gap centering and is not the argmax
baseline. These measurements track behavior; they are not universal statistical
improvement requirements. Review F1 losses together with dispersion reductions.

A bounded real-data check is optional:

```bash
uv run --no-sync python -m benchmarks.threshold_monitor \
  --input dev/raw/hierarchical_plantnet_mini_metric.csv --level 4 \
  --output benchmark-results/hierarchical-level4.json
```

It deterministically selects 2,048 rows at one level before splitting; that level
must have one row per instance. Input hashes are recorded. Performance workloads
remain synthetic so their cost comparisons stay consistent. This small diagnostic
is not a replacement for the original 100-trial studies with larger cohorts.

See [the follow-up findings](threshold_findings.md) for evidence, fixes and limits.

## Optional exact F1 bootstrap aggregation

`OptimalConfidenceThreshold` accepts `n_bootstraps=0` (unchanged default) and
`bootstrap_seed=42`. To try the confidence-space candidate explicitly:

```python
from mini_metrics.metrics import MacroF1, OptimalConfidenceThreshold

thresholds_by_level = OptimalConfidenceThreshold(
    crit=MacroF1, use_quantiles=False, eps=.05,
    n_bootstraps=10, bootstrap_seed=42,
)(calibration_df, verbose=0)
```

Each level must contain one row per calibration instance. The public optimizer
separates levels; the standalone
`mini_metrics.helpers.select_bootstrap_f1_threshold` expects a single level.
It returns a scalar threshold and defaults to confidence space and ten resamples.
The optimizer keeps its existing rejection-rate default and epsilon .01, so use
explicit arguments when reproducing the confidence/.05 study.

Ten resamples cost eleven exact sweeps. The median proposal is accepted only if
its original-calibration F1 is within epsilon of that curve's optimum; otherwise
selection returns the closest eligible **observed confidence**, with a smaller
confidence winning an exact distance tie. This does not guarantee held-out F1 or
stability. Reproducibility requires the same input row order and seed. An integer
seed is local to the call; `None` requests non-reproducible draws.

Bootstrap is used only when the optimizer already qualifies for the exact
Macro/Micro-F1 path. Generic criteria keep the existing sparse search and evaluation
cost even if `n_bootstraps` is positive. This is an optimizer/helper option, not a
new CLI or `evaluate_file` option. Existing CSV goldens are unchanged.

The original paired study follow-up is documented in
[the bootstrap protocol](../dev/experiments/threshold_stability/BOOTSTRAP_PROTOCOL.md).

See [bootstrap findings](bootstrap_findings.md) for the completed paired
comparison: benefits were modest and inconsistent, so the default stays disabled.

Monitor schema 3 retains P/R and threshold dispersion summaries and adds
container workloads. Schema 1/2 reports are incompatible baselines; capture a
fresh baseline after this change. The local comparison for container hardening is
`benchmark-results/container-control-before.json` versus
`benchmark-results/container-control-after.json`.
